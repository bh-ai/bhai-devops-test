# bh_oracle_jar_bh_env_nojar

Standalone PySpark project generated by **bh-bhengine-pyspark** from a BigHammer ENGINE `pipeline.json`.

- Source pipeline: `bh_oracle_jar_bh_env_nojar`
- Detected connection types: Kafka, Oracle, S3

This project is three files: `main.py`, `connections.yml`, `requirements.txt`.

## Prerequisites

- Python 3.9+ with `pip`
- Java 11+ (for Spark) — `pip` cannot install this; `main.py` warns if it is missing
- Network access to download JVM jars on first run (`spark.jars.packages`)
- Reachable Kafka brokers / S3 / JDBC endpoints used by this pipeline

## Setup

No separate pip command is required. On first run, `main.py` installs missing packages from `requirements.txt` using the current Python interpreter.

1. Edit `connections.yml` — confirm `bootstrap_servers`, `bucket`, `region_name`, and other identity fields.
2. Export secret env vars referenced in `connections.yml` (never commit secrets):

_No `*_env` hooks detected; check `connections.yml`._

3. If Kafka uses SSL, place the truststore file at the path in `ssl_truststore_location` (or update that path) and set `ssl_truststore_password_env`.
4. If Kafka uses client auth (`SSL_AUTH` / keystore), also set `ssl_keystore_location` plus `ssl_keystore_password_env` / `ssl_key_password_env`.

## Troubleshooting

| Symptom | Check |
|---|---|
| Wrong / empty Kafka data | Topic in `main.py` `subscribe` option; broker reachability |
| SSL handshake failures | Truststore path + password env; `security_protocol` |
| S3 access denied | AWS env keys or IAM role; bucket/prefix in `connections.yml` |
| Jar download errors | Network / Maven; Spark version vs packages |
